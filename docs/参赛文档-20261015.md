| **参考方向** | 大模型 Agent 能力迁移 / 智能体训练与评测 / 数据蒸馏方法 |

### 项目摘要

我们用一句话概括问题：**把 Agent 能力从教师模型迁移到学生模型时，通常两边跑在不同的 harness（脚手架）上，学生学到的是脚手架痕迹而不是能力。**

CHTD 的做法是让教师与学生跑在**同一个字节冻结的 harness** 上（同一套工具、同一个循环、同一份上下文装配），唯一变量是背后的模型；然后让**学生先跑**，教师在学生的真实岔口上给出决策作为标签，监督只落在学生需要帮助的地方。

在一套完整的对照实验（3 个留出集共 57 题、最多 6 个训练种子、逐题人工与机器双重判读）中，我们得到的结果是：

- **微调确实有效，且效应集中在设计所指向的能力上**：未微调的基线模型在 15 道诊断题上有 **5 道给出完全错误的结论**（判定"代码没问题"、归咎于测试、或编造出题目中不存在的机制；6 次独立判读给出 4–5 道的范围，因基线推理是确定性的，此差异来自判读侧）；而**每一个训练配置都降到 0–2 道**。六个独立配置同时达到这一水平的联合概率 **≤ 3.4 × 10⁻⁹**（即便按最保守假设，仍有 2.6 × 10⁻⁵）。
- **共轨数据有数据效率优势**：仅用 **9 条**学生状态样本，就达到了 **33 条**完整教师演示样本的错误避免水平（6 个种子中 5 个持平或更优）。
- **我们同时量化了评测本身的噪声底**：基线模型完全确定（6 次独立评估产出逐字节相同的答案），而同一个 adapter 两次评估之间会漂移 **0.333 分**——这意味着"用单次 15 题评估比较两个训练臂"在方法上是无效的。这条发现约束了本项目此前所有的臂间比较，我们公开它。

### 问题来源与目标

**问题来自一个具体的失败观察。** 在跨 harness 蒸馏中，学生的训练数据里必然携带教师 scaffolding 的痕迹（特定的工具 schema、重试策略、上下文格式）。一旦学生换到另一套 scaffold 下部署，这些痕迹全部失配，迁移失效。

**目标有两层：**

1. **方法层**：验证"让学生在自己到达的状态上接受教师指导"是否比"让学生学完整教师轨迹"更省数据。
2. **测量层**：在这个过程中，把评测本身做成可信的——包括测量判分器与人类的一致性、计算统计功效、量化评估噪声，并如实记录负面结果（本项目早期有一个臂扫描得到过"无差异"的结论，我们保留并解释了它）。

## 二、技术信息

### AGH（Agnes Harness）在本项目中的作用

AGH 不是容器，而是**实验的不变量本身**。具体承担四件事：

| 作用 | 说明 |
| --- | --- |
| **统一执行循环** | 教师与学生是同一条循环上的两条 route，track 不记录模型身份，因此同一份配方可以解析到任意一侧——这是"唯一变量是模型"这句话能成立的前提 |
| **字节冻结的配方** | 使用内置 `minimal-rl` preset，其字节在加载时校验哈希；一旦漂移就直接加载失败。本项目的 `packages/chtd/` 包自带同类门控 |
| **追加式会话账本** | 每次会话落在一个 append-only 的 ledger（`sessions.db`）里，轨迹可精确重放而不是事后重建；本仓库 `data/` 下累计 **1123 个这样的账本** |
| **fork 与回溯** | 同一个前缀可以被另一条策略继续——这正是"把教师放进学生状态"所需要的机制 |

### Agnes 模型：名称、版本、环节、调用方式

| 项 | 内容 |
| --- | --- |
| **模型名称** | `agnes-3.0-flash` |
| **角色** | teacher（教师）route |
| **调用方式** | OpenAI 兼容协议 `openai-completions` |
| **接入地址** | `https://api.agnes-ai.cn/v1`（凭据经 `secret://teacher/default` 注入，不落盘、不入库） |
| **参与环节** | **全部监督信号的来源**：93 条完整诊断轨迹的每一步 `ls` / `read` / 最终诊断，均由 agnes-3.0-flash 真实执行产生 |
| **产物** | `teacher-demo` v2/v3/v5 数据集（63 / 83 / 93 行），以及用于隔离对照的 teacher-state 数据集 |

**它产出的数据训练出的最强臂**（v5，93 行）在错误避免端点上表现为：15 题仅 1 题失败（约 6.7%），对照基线为 33%。

> **口径说明（重要）**：agnes-3.0-flash 在本项目中承担的是**教师侧数据生产**的角色，学生侧是可替换的小模型。这个分工是 CHTD 方法本身的设计——"共轨"要求两侧可用不同模型，唯一变量是模型身份。模型的替换方法见 `docs/running-with-your-own-models.md`（模型名与 preset 均可配置）。

### 数据 / 代码 / 环境 / 接口

| 类别 | 内容 |
| --- | --- |
| **数据集** | 训练集：教师演示 33/63/83/93 行，学生状态 9 行；评测集：留出 1（15 题）、留出 2（12 题）、留出 3（30 题）、留出 4（48 题）——全部为单缺陷 Python 诊断题，题目 ID 与训练集零重叠（脚本强制校验） |
| **代码** | 本仓库 299 个受跟踪文件，其中 145 个 Python；`harness/` 冻结轨道与冻结门、`distill/` 数据集构建与训练、`eval/` 评测与统计分析、`tests/`（**309 个测试通过**，无需 GPU、无需网络） |
| **训练环境** | 单卡 RTX 4090（48 GB），4-bit NF4 量化 + LoRA（rank 32 / alpha 64 / 30 epochs / 8192 tokens） |
| **推理接口** | OpenAI 兼容 HTTP 端点（`serve_openai_bf16.py`），评估侧经 AGH 客户端以同一条轨道调用 |
| **设备接口** | 无外部硬件；"设备调用"在本项目中即**工具调用**（`ls` / `read` / `find` / `grep` / `shell`），全部经 AGH 策略层（只读/毁坏性/replay 语义）判定并记录 |

## 六、测试样例

任务域为**单缺陷 Python 诊断**：给一个小工具与一个断言脚本，报告"结果不对"，要求指出缺陷位置与机制。判分为三级量表。

### 6.1 正常样例（基线即可解，训练后保持）

| 任务 | 基线 | 训练后（seed0） |
| --- | --- | --- |
| `fix-augmented-assign-mutates` | correct | correct |
| `fix-broad-except` | correct | correct |
| `fix-closure-late-binding` | correct | correct |
| `fix-generator-exhaust` | correct | correct |

> 用途：确认能力没有以牺牲既有正确行为为代价。四个任务覆盖增强赋值语义、异常捕获范围、闭包晚绑定、生成器耗尽四个不同机制。

### 6.2 边界样例（两位人类读者判读不一致）

在留出集 3 的 90 格盲判复核中，**16 格出现分歧**（作者判读 vs 第二位读者，读者在未见作者账本的条件下独立判读）。举例：

| 任务 | 作者 | 独立读者 | 分歧点 |
| --- | --- | --- | --- |
| `h3-split-unbounded`（基线） | correct | partial | 答案指出了 `split(" ")` 未限次与 `maxsplit` 修复，但示例中说错了崩溃形式——是否降级为 partial |
| `h3-round-returns-float`（基线） | correct | failed | 是否认定了缺陷的真实机制 |
| `h3-sorted-descending`（CHTD） | partial | correct | 修复方向正确但解释含糊 |
| `h3-copy-not-deep`（CHTD） | correct | failed | 是否说清了浅拷贝的实际后果 |

> 用途：**这些格子机器判分无法稳定处理**，正是我们主张"机器判读必须先通过人类一致性门控"的依据。分歧率本身（16/90）也是"判分器精度不可能超过人-人一致率"这一结论的实测基础。
